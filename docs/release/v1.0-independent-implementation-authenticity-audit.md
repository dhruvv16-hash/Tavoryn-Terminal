## 4. Workstream B: Security, Reliability, and Operational Safety

### A. HTTP Perimeter Defenses Tested Live Against Port 3787
1. **Host Header Filtering:** Requests with `Host: evil-domain.com` were rejected with `403 Forbidden` (`Tavoryn Terminal only answers to this computer`).
2. **Mandatory Custom Header (`x-qt: 1`):** Mutating requests (`POST /api/trad/order`) without `x-qt: 1` were rejected with `403 Forbidden`.
3. **Origin Validation:** Cross-origin requests with `Origin: http://evil-attacker.com` were rejected with `403 Forbidden`.
4. **Directory Traversal Protection:** Requests containing `/..%2fpackage.json` were rejected with `403 Forbidden` (`file.startsWith(baseDir + path.sep)`).
5. **Double-Encoded Traversal:** Requests with `/%252e%252e/package.json` were rejected with `404 Not Found`.
6. **Dynamic Route Path Traversal:** Requests to `/api/fn/..%2f..%2fpackage` were rejected with `404 Not Found` (regex `^[a-z0-9-]{1,40}$`).
7. **Oversized Payloads:** Request bodies exceeding 2MB were rejected with `413 Payload Too Large`.
8. **Malformed JSON:** Malformed JSON strings (`{ invalid`) were rejected with `400 Bad Request`.

### B. Pre-Trade Risk Gateway Verification
All 16 reported pre-trade risk controls (and 5 sub-spec controls, totaling 21 distinct rejection codes) in `lib/broker/risk-gateway.js` were audited and verified fail-closed:
- `KILL_SWITCH_ACTIVE`: Halts trading when kill-switch is engaged unless `isKillSwitchFlatten: true`.
- `INVALID_ORDER_SPEC`: Rejects missing specs, invalid symbols, non-numeric quantities, and invalid limit/stop prices.
- `DISALLOWED_ORDER_TYPE`: Rejects unapproved types (e.g. MOO/MOC).
- `DISALLOWED_INSTRUMENT`: Enforces whitelist symbol bounds.
- `STALE_OR_DEGRADED_FEED`: Halts orders if feed status is DEGRADED, STALE, ERROR, or DISCONNECTED.
- `FEED_STALE`: Rejects orders if feed timestamp age exceeds 15,000 ms.
- `MISSING_MARKET_PRICE`: Rejects orders if no valid market or limit price can be established.
- `MAX_ORDER_QTY_EXCEEDED` & `MAX_ORDER_NOTIONAL_EXCEEDED`: Hard single-order caps.
- `RATE_LIMIT_EXCEEDED`: Rolling 60-second order throttle (default 60/min).
- `MAX_OPEN_ORDERS_EXCEEDED`: Prevents runaway algorithmic order floods.
- `DAILY_LOSS_LIMIT_REACHED`: Halts opening orders when cumulative intraday loss reaches limit; allows risk-reducing closing exits.
- `UNKNOWN_BUYING_POWER` & `INSUFFICIENT_BUYING_POWER`: Fail-closed check against available purchasing power.
- `MAX_POSITION_EXPOSURE_EXCEEDED`: Rejects post-fill concentration violations.
- `INVALID_CLOSING_ORDER` & `CLOSING_QTY_EXCEEDS_POSITION`: Blocks fake closing exemptions and position reversals.
