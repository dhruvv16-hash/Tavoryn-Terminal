## 1. System Requirements & Architecture

Tavoryn Terminal is designed as an **offline-first, zero-install, single-binary-like financial workspace**. It requires no external runtime build steps, no package manager installations (`npm install` is not required), and no database daemons.

### Minimum System Requirements
- **Runtime:** Node.js v18.0.0 or higher (Verified on Node.js v24.19.0).
- **Operating System:** Windows 10/11 x64, macOS 12+ (Apple Silicon or Intel), or Linux x64/arm64.
- **Hardware:** 2 CPU cores, 1 GB available RAM, 100 MB free disk space.
- **Browser:** Any modern Chromium-based browser, Firefox, or Safari (WebSocket & Canvas support required for charts).
- **Network:** Optional for offline research and backtesting; active Internet connection required for live market feeds.

## 2. Quick Start & Execution

Because Tavoryn Terminal has zero external runtime dependencies, it can be launched immediately from source.

### Option A: Standard Interactive Launch
```powershell
npm start
```
*Starts the server on `http://localhost:3787` and automatically opens the user's default web browser.*

### Option B: Headless / Terminal-Only Mode
```powershell
npm run serve
```
*Starts the server without launching a browser window.*

### Option C: Native Platform Launchers
- **Windows:** Double-click [`start.bat`](file:///D:/G_BLOOM/Tavoryn-Terminal/start.bat) or run `.\start.bat` in PowerShell.
- **macOS:** Double-click [`start.command`](file:///D:/G_BLOOM/Tavoryn-Terminal/start.command).
- **Linux:** Run `./start.sh`.

### Option D: Background Daemon Management
To start the terminal as a background daemon that persists after closing the console:
```powershell
node scripts/launch.js
```
To cleanly stop the running background daemon:
```powershell
node scripts/stop.js
```

## 4. Configuration & Environment Variables

Tavoryn Terminal requires zero configuration files by default. Fine-grained operational behavior can be controlled via standard environment variables:

| Variable | Default Value | Description |
| :--- | :--- | :--- |
| `PORT` | `3787` | Preferred HTTP listening port. If busy, the server automatically scans the next 20 ports. |
| `HOST` | `127.0.0.1` | Network interface to bind. Default binds strictly to localhost. |
| `QT_DATA_DIR` | `./data` | File system directory where workspace states, watchlists, drawings, and paper accounts are stored. |
| `TAVORYN_PAPER_STORE_KEY` | `paper-account` | Base filename for the active paper trading account ledger. |
| `QT_OPEN` | `0` | Set to `1` to force opening the browser on startup. |
| `NODE_NO_WARNINGS` | `0` | Set to `1` to suppress experimental runtime warnings. |

## 5. Operations & Workspace Management

### A. Pre-Configuring Workspace Layouts (`scripts/setup.js`)
You can pre-configure the four terminal panels for specific asset classes before launching the application:

```powershell
node scripts/setup.js --profile stocks --ticker NVDA
node scripts/setup.js --profile crypto --ticker BTC
node scripts/setup.js --profile fx --ticker EURUSD
node scripts/setup.js --profile macro
node scripts/setup.js --profile mix
```

Available Profiles:
- `stocks`: WEI (World Equities), TOP (News), `<ticker> GP` (Chart), MOST (Market Movers).
- `crypto`: CRYPTO (Coins), TOP CRYPTO, `<ticker> GP`, WIRP (Rate Path).
- `fx`: FXC (Forex Crosses), ECO (Economic Calendar), `<ticker> GP`, CBRT (Central Banks).
- `macro`: WIRP, GC (Yield Curve), ECO, GLCO (Global Commodities).
- `mix`: WEI, TOP, WIRP, ECO.

### B. Custom Technical Indicators ("Pine Scripts" in JS)
Analysts can add custom technical indicators without modifying source code. Place a plain JavaScript module in the `custom/` directory exporting a default object:

```javascript
// custom/my-momentum.js
export default {
  name: "My Momentum",
  calc(bars, params, ta) {
    const period = params.period || 14;
    return bars.map((b, i) => {
      if (i < period) return { time: b.time, value: null };
      return { time: b.time, value: b.close - bars[i - period].close };
    });
  }
};
```
The server hot-reloads the indicator automatically and registers it under `custom:my-momentum`.

### C. Excel & Python Integration (Bloomberg Emulation Routes)
The terminal includes Bloomberg BDP and BDH emulation endpoints that allow direct consumption from Excel (`Data > From Web`) or Python (`pandas.read_csv`):
- Snapshot: `http://localhost:3787/api/bdp?ticker=AAPL&field=PX_LAST&format=csv`
- Historical: `http://localhost:3787/api/bdh?ticker=AAPL&field=PX_LAST&start=2024-01-01&format=csv`

## 6. Operational Troubleshooting & Runbooks

### Incident 1: Port 3787 Already in Use
- **Behavior:** The terminal automatically increments the port and binds to the first available port (e.g. `3788` or `3789`).
- **Resolution:** Check terminal output for the active URL or stop the existing instance:
  ```powershell
  node scripts/stop.js --all
  ```

### Incident 2: File Lock on Windows (`EPERM` / `EBUSY`)
- **Behavior:** Windows Search Indexer or Antivirus locks a JSON file in `data/` during atomic rename.
- **Resolution:** Handled automatically by `lib/store.js`, which detects Windows lock codes and writes in-place to prevent data loss.

### Incident 3: Upstream Rate Limiting (HTTP 429)
- **Behavior:** Free public providers (e.g. FairEconomy calendar or Yahoo Finance) momentarily throttle unauthenticated requests.
- **Resolution:** 
  1. The UI displays an alert badge without crashing.
  2. Fallback providers (e.g. Coinbase for Binance, Nasdaq for Yahoo) are engaged automatically.
  3. Wait 60 seconds for upstream rate-limit token replenishment.

### Incident 4: Corrupted Paper Account Recovery
- **Behavior:** The system detects invalid JSON in `data/paper-account.json`.
- **Resolution:** The engine automatically preserves the corrupted file as `data/paper-account.corrupted.<timestamp>.json` and initializes a fresh ledger, preventing unrecoverable data loss.
