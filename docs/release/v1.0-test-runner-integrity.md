## 2. Test Discovery & Harness Architecture

### A. Offline Test Suite Runner (`scripts/test.js`)
```javascript
// scripts/test.js
import { readdirSync } from "node:fs";
import { spawnSync } from "node:child_process";

const files = readdirSync(new URL("../test/", import.meta.url))
  .filter((f) => f.endsWith(".test.js") && f !== "live.test.js")
  .map((f) => `test/${f}`);

const r = spawnSync(process.execPath, ["--test", ...files], { stdio: "inherit" });
process.exit(r.status ?? 1);
```

#### Discovery Mechanics
- **Dynamic File Enumeration:** Reads the `test/` directory using Node.js `readdirSync`. Any new test file matching `*.test.js` is automatically discovered without requiring manual registration.
- **Excluded Suites:** Excludes only `test/live.test.js` to ensure the offline test suite runs 100% deterministically without external network dependencies.
- **Native Test Runner:** Spawns `node --test` natively, executing all discovered suites using Node.js built-in test runner.
- **Exit Code Propagation:** Captures `r.status` from the child process and passes it directly to `process.exit(r.status ?? 1)`. If any assertion fails in any test file, `node --test` exits with code `1`, causing `scripts/test.js` to exit with code `1`.

### B. Release Check Pipeline (`scripts/check.js`)
```javascript
// scripts/check.js lines 10-25
const steps = [
  ['Offline tests', [process.execPath, path.join(root, 'scripts', 'test.js')]],
  ['Data sources', [process.execPath, path.join(root, 'scripts', 'doctor.js')]],
  ['Live smoke test', [process.execPath, path.join(root, 'scripts', 'smoke.js')]],
];
const results = [];
for (const [name, [cmd, ...args]] of steps) {
  process.stdout.write(`\n=== ${name} ===\n`);
  const r = spawnSync(cmd, args, { cwd: root, stdio: 'inherit', env: { ...process.env, NODE_NO_WARNINGS: '1' } });
  results.push([name, r.status === 0]);
}
console.log('\n=== Summary ===');
for (const [name, ok] of results) console.log(`${ok ? 'PASS' : 'FAIL'}  ${name}`);
const ready = results.every(([, ok]) => ok);
process.exit(ready ? 0 : 1);
```

#### Multi-Stage Verification Pipeline
- Step 1: Executes `scripts/test.js` (604 offline tests).
- Step 2: Executes `scripts/doctor.js` (6 live data feeds).
- Step 3: Executes `scripts/smoke.js` (19 live smoke endpoints on an ephemeral server).
- **Cumulative Check Count Provenance:**
  $$604 \text{ (offline unit tests)} + 6 \text{ (data feed checks)} + 19 \text{ (live smoke screens)} = 629 \text{ total release checks}$$
- **Fail-Closed Gating:** If any step fails (`r.status !== 0`), `ok` evaluates to `false`, and `ready` becomes `false`, causing `check.js` to exit with code `1`.

## 3. Deliberate Failure Injection & Error Propagation Test

To independently prove that the test runner does not suppress failures or report synthetic passes, a deliberate assertion failure was injected into the test directory:

### Failure Injection Code
Created temporary test file: `test/deliberate_fail.test.js`:
```javascript

import assert from 'node:assert/strict';

test('deliberate', () => {
  assert.equal(1, 2);
});
```

### Execution Against `node scripts/test.js`

### Findings
1. **Dynamic Inclusion:** The test runner automatically discovered the new test file (total tests increased from 604 to 605).
2. **Assertion Detection:** The failed assertion was detected immediately and output to stderr with file path and line number.
3. **Exit Code Propagation:** `scripts/test.js` exited with exit code `1` (`ScriptsTestExitCode: 1`).
4. **Clean Cleanup:** `test/deliberate_fail.test.js` was unlinked, returning the test suite to 604 passing tests.

## 4. Live Smoke Test Harness Audit (`scripts/smoke.js`)

The live smoke test harness was inspected for execution realism:
- **Port Isolation:** Generates an ephemeral random port: `String(3700 + Math.floor(Math.random() * 90))` to prevent port collisions with running production instances.
- **Data Isolation:** Isolates paper data to `QT_DATA_DIR: path.join(root, 'data', 'smoke')`, completely insulating the protected baseline file `data/paper-account.json`.
- **Live HTTP Requests:** Slices real HTTP requests to the ephemeral server using native `fetch`:
  - Validates HTML page rendering (`/`)
  - Validates chart engine bundle (`/vendor/lightweight-charts.standalone.production.js`)
  - Validates API endpoints: `/api/health`, `/api/candles`, `/api/quotes`, `/api/fn/board`, `/api/fn/top`, `/api/fn/des`, `/api/fn/cf`, `/api/fn/hds`, `/api/fn/omon`, `/api/fn/eco`, `/api/fn/gc`, `/api/fn/btmm`, `/api/fn/wirp`, `/api/fn/ecst`, `/api/fn/cbrt`, `/api/fn/cot`.
- **Graceful Cleanup:** Issues `POST /api/shutdown` with header `x-qt: 1` and kills the child process after completion.
