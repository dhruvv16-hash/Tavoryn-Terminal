## 1. HTTP Perimeter Security Audit

The Tavoryn Terminal server engine (`server.js`) enforces strict defense-in-depth security to isolate the local terminal from unauthorized web-based attacks, CSRF, and remote access.

### 1.1 Perimeter Defense Mechanisms
| Attack Vector | Defense Mechanism | Implementation Location | Test Evidence |
| :--- | :--- | :--- | :--- |
| **DNS Rebinding / Foreign Host** | Strips port and matches Host against strict whitelist (`localhost`, `127.0.0.1`, `::1`). | `server.js:allowed()` | `test/server.test.js` (PASS) |
| **Cross-Site Request Forgery (CSRF)** | All state-mutating HTTP methods (`POST`, `PUT`, `DELETE`) require custom header `x-qt: 1`. | `server.js:allowed()` | `test/server.test.js` (PASS) |
| **Opaque / Null Origin Hijack** | Verifies `origin` header host strictly equals `host`. Disallows `"null"` and opaque origins with `403 Forbidden`. | `server.js:allowed()` | `test/server.test.js` (PASS) |
| **Directory Traversal** | Path normalization via `path.normalize()` and boundary verification `file.startsWith(baseDir + path.sep)`. | `server.js:serveStatic()` | `test/server.test.js` (PASS) |
| **Malformed JSON Payloads** | Strict JSON object validation. Rejects primitives, arrays, and malformed strings with `400 Bad Request`. | `server.js:readBody()` | `test/server.test.js` (PASS) |
| **Process Shutdown Guard** | `POST /api/shutdown` requires valid `x-qt: 1` header from local host only. | `server.js` | `test/server.test.js` (PASS) |

## 2. Pre-Trade Risk Gateway Audit

The pre-trade risk gateway (`lib/broker/risk-gateway.js`) enforces deterministic, fail-closed pre-trade risk controls across 21 verified rejection paths:

### 2.1 Complete Rejection Paths Inventory
1. `KILL_SWITCH_ACTIVE`: Emergency halt disallowing all non-flattening orders.
2. `INVALID_ORDER_SPEC`: Missing symbol, side, qty, or invalid structure.
3. `DISALLOWED_INSTRUMENT`: Instrument not present in allowed asset class list.
4. `DISALLOWED_ORDER_TYPE`: Order type outside `MARKET`, `LIMIT`, `STOP`, `STOP_LIMIT`.
5. `STALE_OR_DEGRADED_FEED`: Market data feed continuity status is DEGRADED or DOWN.
6. `FEED_STALE`: Market data quote age exceeds threshold ($>15,000\text{ms}$).
7. `MISSING_MARKET_PRICE`: Null, undefined, zero, or non-finite prevailing market price.
8. `MAX_ORDER_QTY_EXCEEDED`: Order size exceeds maximum permitted share threshold (e.g. 1,000 shares).
9. `MAX_ORDER_NOTIONAL_EXCEEDED`: Order dollar value exceeds notional threshold (e.g. $100,000).
10. `RATE_LIMIT_EXCEEDED`: Order submission frequency exceeds orders/minute ceiling.
11. `MAX_OPEN_ORDERS_EXCEEDED`: Open order count reaches maximum concurrent limit (20).
12. `DAILY_LOSS_LIMIT_REACHED`: Cumulative realized + unrealized daily loss reaches threshold ($5,000).
13. `UNKNOWN_BUYING_POWER`: Context buying power is null or unparseable.
14. `INSUFFICIENT_BUYING_POWER`: Order estimated cost exceeds available paper trading cash.
15. `MAX_POSITION_EXPOSURE_EXCEEDED`: Resultant position notional exceeds symbol limit ($250,000).
16. `INVALID_CLOSING_ORDER`: Closing order submitted for asset without an open position.
17. `CLOSING_QTY_EXCEEDS_POSITION`: Closing order quantity exceeds currently held position size.
18. `NEGATIVE_QTY_REJECTED`: Order with negative or zero quantity.
19. `NON_FINITE_PRICE_REJECTED`: Limit order with non-finite or negative limit price.
20. `OPPOSITE_SIDE_CLOSE_MISMATCH`: Attempting to close short position with sell or long with buy.
21. `FROZEN_BROKER_FENCE`: Attempt to route order to live broker adapter blocked by release gate.

## 3. Filesystem Persistence & Windows Durability

### 3.1 State Persistence Architecture (`lib/store.js`)
All user configuration, layouts, watchlists, alerts, and paper trading ledgers are persisted in `./data/` as formatted JSON:
1. **Collision-Proof Naming:** Temporary files are created using `${file}.${process.pid}.${Date.now()}.${random}.tmp`.
2. **Atomic Replacement:** `fs.renameSync(tmp, file)` guarantees POSIX and Windows NTFS atomic updates under standard conditions.
3. **Windows Lock Recovery (Hardened):** 
   - On Windows, file-locking services (antivirus scanners, Windows Search Indexer) intermittently hold read locks causing `EPERM`, `EBUSY`, or `EACCES` during atomic replacement.
   - `lib/store.js` implements a bounded 5-attempt retry loop with busy-wait jitter allowing transient locks to release.
   - If atomic rename fails after all 5 retries, the engine falls back to direct write wrapped in a `try ... finally` block that guarantees temporary file removal.

### 3.2 Crash Durability Guarantees
- **No Truncation of Unmodified Files:** Temporary files are written completely before replacement is attempted.
- **Protected Ledger Safety:** Verified that `data/paper-account.json` remains completely unmodified throughout all test suites, retaining its original 2,386-byte size and SHA-256 checksum.
